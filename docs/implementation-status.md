# Nekodex 实现状态

日期：2026-09-17。本文区分代码实现、构建检查、部署状态与真实运行证明。

## 当前结论

产品边界已收窄为只读跨设备监控。PC 与 Android 加载同一份随应用安装的 React 页面；Poke3 不访问 NixOS WebUI。设备组仍采用局域网认证直连，一次入组后可读取组内来源电脑公开的监控数据。

该边界现已冻结为当前开发基线：后续实现只补齐监控数据正确性、组网可靠性、离线恢复、跨平台运行和性能，不在现有协议、界面或缓存路径中恢复任何会话控制。若未来重新评估控制能力，必须另立方案和兼容性、安全性验收，不能作为本阶段的顺带扩展。

远程创建任务、发送或追加消息、停止任务、处理审批及控制命令恢复不再属于当前产品。协议保留旧枚举以兼容解码，但当前能力集不声明它们；来源服务和 Tauri 请求入口再次拒绝非监控操作。旧控制面板、草稿恢复 UI、隐藏的 App Server 控制探针及其 Tauri 命令已经移除。

## 已实现的监控纵切

- 设备身份安全存储、SQLite 公共状态、创建组、PAKE 邀请、人工确认加入、签名成员事件、防回滚检查点和成员撤销。
- Noise XX 加密 WebSocket、mDNS 发现、手工地址、认证地址持久化、心跳和退避重连。
- 业务主/次版本及操作级能力协商；未知、未协商或当前禁用的操作在副作用前失败。
- 查看端网络客户端在发送业务帧前也会核对当前认证连接实际协商出的操作能力；直接调用通用 Tauri 读取入口不能把未协商操作发给对端，来源端仍保留独立的监控操作白名单作为最终边界。
- 新节点额外协商 `codex.business.transport.base64-payload.v1`，把业务 JSON 以紧凑 Base64 放入 Noise 帧，避免旧字节数字数组约四倍膨胀。能力未交集时仍发送旧格式；旧格式响应超过最终 65,535 字节帧上限时改回小型 `SourceUnavailable`，不会让认证连接一起断开。
- 有界业务队列、事件优先级、慢消费者恢复信号和 `events.replay` 有界回放。
- 来源电脑项目白名单和独立 App Server 生命周期；Android 仅为监控端。
- 额度、日用量、项目、会话列表、会话详情、活动以及待审批状态读取。
- 多个查看端并发读取来源状态时，共用 15 秒的成功快照并合并刷新，避免重复读取额度、用量和扫描会话；失败结果不进入缓存。
- 总览、额度和活动页在相邻切换时共用按目标连接状态及能力隔离的 10 秒请求结果；用户手动刷新始终绕过该缓存。
- 事件 revision 在写入时原子递增，不再每 2 秒遍历事件缓存；会话页只在审批事件、当前来源活动或当前详情所属会话的活动发生变化时分别刷新审批、会话列表或详情，不新增独立高频后端轮询。
- 按来源隔离的离线缓存、采集时间、100MB 全局可恢复监控数据淘汰上限和分页游标；预算同时统计普通请求缓存与持久化活动事件，成员、项目及来源世代标记不参与淘汰。
- 界面已区分设备连接状态、已确认的本机来源健康状态和读取失败后的缓存回退；远端设备在线不再被表述为远端来源服务可用。来源进程终止后，本机和远端读取都会在进入后端前立即返回来源不可用，并允许只读请求查询缓存；权限、版本、参数等其他协议错误仍直接暴露，不会被缓存掩盖。
- 网络快照会完整暴露离线、连接中、在线、身份验证失败和不兼容状态；前台页面每 5 秒低频检查一次，状态无变化时不更新 React 状态，避免墨水屏无意义重绘。
- 会话页可见时每 5 秒读取一次轻量来源健康状态，daemon 或独立 App Server 退出后会及时切换为不可用；来源启动和重启操作带有并发保护，不会因重复点击并行重建网络。
- 总览中的运行中、需关注和额度汇总会标明缓存来源；项目列表会完整遍历来源分页；待审批来源不可读时不再误报为“暂无”，并保留、标记上次可见结果。
- 总览、额度和活动页都会传播共享实时来源/历史回退来源语义；历史回退数据仍可阅读，但不会被描述成实时会话或完整审批视图。
- 额度、日用量和会话统计分别读取并携带字段级错误；其中一项失败不会再丢弃同一来源中仍然可用的其他监控数据。总览、额度和活动页会明确提示部分来源仅部分可用。
- 同账户多来源快照使用确定性择优：先比较采集时间，同秒优先共享实时来源，仍相同时按来源 ID 固定排序；设备枚举顺序不会改变额度或日用量归属。
- WebView 回到前台时会主动重新投递已记住的局域网地址，再刷新设备状态，作为 Android 原生恢复事件之外的补充恢复路径。
- Android 前台连接服务只在 Rust 局域网服务成功启动后运行；网络启动失败时会停止通知，避免显示并不存在的后台连接。
- Android Debug 与 Release 现在都允许局域网 `ws://` 作为 Noise 会话载体；此前只有 Debug 覆盖为允许，Release 会在进入应用层加密认证前被 Android 明文流量策略直接拦截。该设置不把业务内容降级为明文，Noise XX 仍负责成员认证和载荷加密。
- Android 前台服务被系统单独回收、但应用进程及 Rust 核心仍存活时允许系统恢复服务并重新取得多播锁；若整个进程已被回收，进程内存活标记随之消失，服务不会仅凭旧通知伪装核心仍在线。显式退出设备组或网络启动失败会先撤销该标记再停止服务。
- 加入设备组的最后解密、名册校验或持久化步骤失败时，会恢复原有本机身份和“尚未加入”状态，允许用户修正后重试。
- 邀请现在携带设备组显示名称，并把它与组 ID、邀请者/加入者身份及随机数一起绑定进 PAKE 上下文；加入端不再把组名硬编码为“我的设备”，篡改名称会导致双方确认失败。加入成功后还会把已认证邀请者 ID 与加入 URL 的设备地址持久化，作为 mDNS 后续不可用时的重连后备。
- mDNS 服务记录会同时公布当前检测到的全部局域网 IP，不再只取地址列表第一项；多网卡电脑上的设备发现与邀请公告因此和界面展示的候选地址范围一致，最终身份仍只由 Noise 成员证明决定。
- WebView 或 Android 原生生命周期恢复时，局域网服务会重新读取当前网卡地址，刷新自身地址过滤、mDNS 浏览器与公告，同时保留尚未完成邀请的到期信息，再投递已记住的成员地址进行重连。Wi-Fi 切换或系统恢复后不再继续只使用启动时的发现实例与旧地址。
- 局域网服务还会每 60 秒低频比较一次本机非回环地址；只有地址实际变化时才更新公告并重建发现浏览器。该后端检查不依赖桌面窗口可见性，因此窗口长期隐藏或 Android WebView 暂停时发生换网也能自行恢复，又不会每轮无条件重启 mDNS。
- 邀请中的手工连接地址由 `SocketAddr` 统一格式化，IPv6 会携带标准方括号，不再因直接拼接端口生成无法解析的歧义地址。
- 创建、加入和本机重命名统一拒绝空名称及超过 128 字符的设备组/设备名称，避免未经约束的显示字段放大邀请、成员日志和设备列表载荷。
- 加入握手现在还会在 PAKE、签名、AAD 构造和持久化前校验远端邀请、Hello、双方确认、成员 profile 与加密 envelope 的所有字符串和可变字节字段；超长组名、设备标识、PAKE 消息、profile 或证明会整帧拒绝，不依赖 65 KiB WebSocket 上限兜底，也不会截断后继续认证。
- 完整成员历史现在限制为 12 KiB、最多 256 个签名事件；成员/事件/父事件标识最多 128 字节，单事件最多 64 个父引用，显示名最多 128 字符和 512 字节。12 KiB 为现有 JSON 字节数组、加密密文、Noise 与 65 KiB 加入帧保留封装余量；解密、恢复、同步合并、本机成员变更和 SQLite 写入都会在采用前拒绝超限状态。
- 新成员变更只引用当前已认证因果前沿，不再把完整历史检查点复制进每个事件的 parents；合法成员持续重命名也不能让成员日志或数据库无限增长，达到边界时本次变更原子失败并保留原状态。
- 创建组和加入组现在把组资料、本机资料、成员事件与检查点放在同一 SQLite 事务中提交；失败不会留下只有部分表可见的“半个设备组”。后续成员状态提交也会在同一事务中确认设备组仍然存在，因此退出清理与迟到的加入/同步提交不会让旧组状态复活。创建失败会直接恢复为可重试的未加入状态，不再要求重启应用重新初始化。
- 初始化、创建/加入/退出组、成员变更、手工连接、来源切换和本机项目写操作共用本机状态变更串行门。退出设备组不能再与旧来源重启或项目写入交错，避免未加入状态下旧网络、来源或项目重新出现。退出清理失败尝试恢复旧组服务时也会重新协调 Android 前台服务，恢复失败不会保留虚假在线通知。
- 成员撤销后，网络层在发送和接收业务请求前都会重新核对当前成员资格；只关闭被撤销设备的连接，不再中断其他合法成员。该来源的请求缓存、活动事件、游标、项目记录和记住的地址会从本机清除，缓存读取也拒绝已经失效的目标。
- 新成员加入、本机改名或成员撤销提交后，会通过现有 Noise 认证连接的有界内部控制队列广播完整签名成员包。该帧不属于监控业务 capability，也不会进入活动事件与离线缓存。接收端复用成员同步校验并原子落库；发现本机已被撤销时立即关闭全部组连接，发现其他已连接节点被撤销时立即关闭对应连接。队列拥塞不会阻塞其他节点或回滚已经提交的成员变更，而是关闭该慢连接，让下一次认证重连通过握手同步最新成员状态。
- 本机来源事件在发布时直接写入 SQLite，消除来源启动到网络订阅建立之间的丢失窗口；网络服务启动时恢复最近 1000 条持久化事件，因此应用重启后活动页仍可显示离线历史。接收事件会先通过 SQLite 的来源、世代和游标冲突检查，再进入内存缓存；重复回放不占用内存窗口，冲突载荷也不会短暂进入页面事件流。本地广播发生积压时按本机来源和最新进程世代恢复持久化窗口，并通知远端执行回放；不会把其他来源或旧世代事件混入。来源进程世代变化时不跨世代续用游标，重新读取当前状态。
- 每条新认证连接建立后，只要双方协商了 `events.replay`，查看端就会立即从该来源已持久化的最新位置启动一次有界回放；不再依赖后续队列溢出或落库失败才发现断线期间缺失的活动。连接 token、来源、进程世代、严格递增游标与 1000 条窗口校验仍在每批落库前执行。
- 来源服务的回放队列拒绝其他来源或其他进程世代的事件；持久化恢复位置按实际落库顺序确定，不依赖可能重复或回拨的系统时间。
- 事件回放要求游标严格递增，且同世代回放必须越过请求游标；任何 SQLite 持久化失败都会让恢复失败并保留可见告警。实时事件落库失败时会主动请求有界回放，不再把内存或磁盘缺口当作恢复成功。
- 来源进程世代使用 WebView 可精确表示范围内的随机标识，不再由系统时间推导；时钟回拨不会让新进程与旧事件世代碰撞。
- PC/Android 共用安装内 React + TypeScript 页面和电子墨水主题。
- Tauri 发布配置已启用平台安装包产出；开发时仍可显式使用 `--no-bundle`。Android 主 Activity 与生成的 `TauriActivity` 位于同一应用包，直接继承而不引用旧模板包名；生成目录中的机器相关 Gradle 路径保持忽略并由 Tauri CLI 在构建机上生成。
- Android 前台服务与恢复重校验；桌面关闭窗口后只隐藏主窗口并维持来源和网络任务，托盘可重新显示窗口。托盘显式退出会先断开局域网连接并停止桌面来源服务，再终止应用；该托盘与关闭窗口逻辑仅编译到桌面端，不影响 Android 生命周期。
- 本机项目添加、编辑、删除和来源服务重启；这些是本机维护，不是远程会话控制。
- 本机项目白名单维护不再依赖 App Server 来源进程当前在线：增删改会先持久化并清理旧读取缓存，来源在线时立即同步，来源不可用时由下次启动载入。来源故障不会阻止用户修正项目范围后再重启来源。
- 独立 App Server 返回 `notLoaded` 时，界面会明确标记为“历史记录 · 实时状态不可见”，总览也不会用零运行数冒充实时统计。待审批区域明确限定为 Nekodex 来源连接实际收到的请求，不把其他独立 Codex 客户端的未知状态误报成“暂无”。
- 共享 daemon 中会话的 `waitingOnApproval` 只读状态会补充成无处理按钮的会话级提醒；详细审批请求仍只在来源连接实际收到时显示。待审批列表在页面可见时每 15 秒低频重读，避免依赖可能只发给原客户端的通知。
- 总览统计和共享 daemon 的会话级待审批补充会逐页扫描 App Server 会话，设置 2 万条有界上限；达到上限时总览显示不完整计数，待审批页明确提示无法完整确认。待审批业务接口提供稳定的本地分页，统一前端会持续读取全部页，并拒绝重复游标或超过安全页数的异常来源。
- 待审批分页游标绑定最后一个审批 ID，而不是动态数组下标；审批在两页之间新增或过期时不会因前部位移而漏掉后续项目。会话列表使用单一有效请求序号、加载锁和线程 ID 去重，详情只接受最后一次选择/刷新对应的响应；切换或删除项目会同步清除旧列表和详情。
- 来源目标、成员、连接状态和能力的并发刷新使用单一有效请求序号；较早发起但较晚完成的 IPC 快照不能在成员撤销或网络变化后重新选回旧目标。
- 总览/额度聚合刷新与活动页完整刷新、事件刷新分别使用单一有效请求序号；切页、恢复前台、定时刷新和手动刷新并发时，旧结果不能覆盖后完成的新结果。
- 历史回退来源不会从持久化的 `waitingOnApproval` 状态推导实时审批；只有共享 daemon 模式启用该补充提醒。
- 本机项目白名单新增、编辑或删除前会清除该来源的请求缓存，避免来源随后不可用时继续展示已经撤销的本机项目或会话缓存；其他设备来源的缓存不受影响。
- 会话详情不再接受任意已知 thread ID 直接读取：来源服务先在所选项目（未选择时为全部白名单项目）的有界会话列表中确认归属，无法完整确认时明确失败，不会绕过项目白名单。项目变更会同时废弃旧会话和审批分页游标。
- 会话详情现在以稳定 turn ID 向更早历史分页：首屏读取最新 20 个回合，每次可再加载更早 20 个，最多在 Poke3 页面保留 100 个。来源先读取轻量会话元数据，再使用 App Server 的只读 `thread/turns/list` 摘要分页，避免 `thread/read(includeTurns=true)` 把超大历史一次性载入来源进程。分页游标绑定项目范围、thread、页大小、是否读取回合及项目代次；未知、过期或跨上下文游标明确拒绝，项目变化立即失效。每页受 12 KiB 结果预算和单条正文预算约束；该保守预算同时兼容尚未协商紧凑帧的旧节点，因预算裁剪的回合会成为下一页边界，不会静默跳过。
- 若较旧 Codex App Server 明确以 JSON-RPC `-32601` 表示不支持 `thread/turns/list`，来源才回退到只读 `thread/read(includeTurns=true)`，随后仍执行同一白名单校验、分页投影和字节预算；其他服务器错误不会被误判成兼容性问题。分页响应缺少 `data` 数组或返回非法 `nextCursor` 时明确失败，不再静默显示为空会话。
- 已由白名单会话列表确认过的 thread ID 会按项目范围缓存在来源进程中，正常的“列表→详情”路径不再为每次详情读取重复扫描最多 2 万条会话；缓存上限为 2 万条，且项目白名单变化时立即清空。缓存未命中仍执行完整边界检查，不会因优化绕过白名单。
- 本机项目路径在保存前规范化为真实绝对目录，并拒绝与现有项目重复或形成父子嵌套；编辑项目时只排除当前项目自身，避免一个会话被多个项目边界重复扫描。
- Windows 项目目录会在持久化、重复/父子判断及来源端会话扫描作用域中统一去除扩展路径前缀、规范分隔符并按平台大小写语义比较；项目进入来源服务时只执行一次文件系统 canonicalize，并把规范项目表与无效路径集合原子替换，后续监控读取只使用内存键。因此盘符大小写、`\\?\`、UNC、`..` 或符号链接等价形式不会生成不同的会话游标与扫描缓存边界，也不会在每次监控请求中重复阻塞文件系统。
- 状态快照和已认证来源事件都会记录来源进程世代；首次识别世代或世代变化时，先清除该来源的旧请求缓存再写入新世代标记，避免来源重启后继续展示上一世代的项目、会话或审批缓存。世代标记不参与普通请求缓存的 LRU 淘汰；事件接收与回放还会核对当前连接 token，已被新连接替换的旧连接不能把世代标记回退。
- 项目白名单、来源模式或设备组状态变化时也会立即清除前端 10 秒共享快照，避免切换页面或重新入组后短暂复用旧统计。
- 统一读取路径会在目标明确离线或本机来源不可用时先读取本机缓存，不再先等待最长 30 秒的远端请求；目标重新在线后，目标状态键变化会触发实时刷新。缓存提示只陈述缓存采集时间，不再误称一定发生过一次来源请求失败。
- 在线成员的监控能力尚未协商完成或明确不支持某项读取时，界面仍允许读取该来源已有的本机缓存，但不会绕过能力协商发送在线请求；能力元数据随后到达后才恢复实时读取。短暂缺失能力列表不再把可用离线内容误判为完全不可读。
- 电脑来源启动时优先通过官方 `codex app-server proxy` 连接已经运行的本地共享 daemon；不可用时才启动独立 stdio App Server。来源模式随只读状态快照跨设备传递，PC/Poke3 都会明确显示“共享实时来源”或“历史回退来源”。应用不会在后台擅自修改 daemon；用户可在本机界面明确点击“启用共享实时来源”，启动官方 daemon 后立即重接来源。

## 只读边界

当前对外能力只有 `projects.list`、`state.subscribe`、`events.replay`、`threads.list`、`threads.read` 和 `approvals.list`。

`threads.create`、`turns.send`、`turns.steer`、`turns.interrupt`、`approvals.resolve` 和 `commands.get` 均不被声明，并由来源服务及平台入口拒绝。待审批页面只显示来源、会话和描述，提示用户在来源电脑的 Codex 客户端中处理。

协议仍保留旧控制操作的 wire 枚举，使旧节点请求能得到确定的“不支持”响应；App Server 适配器不再公开创建/恢复会话、发送/转向/中断轮次、提交审批结果或回复审批服务端请求的构造 API，仅保留初始化通知和监控读取请求。App Server 运行时的任意 `Outbound` 发送接口也已改为专用 `initialized()`，且 `Outbound` 字段不再公开，调用者不能在通用请求闭包中手工构造任意 JSONL 绕过适配器；运行时 6 项聚焦测试与 `nekodex-shell` 静态检查通过。来源服务中的控制执行代码也已经删除。审批请求的只读解析仍保留，用于展示待审批状态。设备核心不再公开命令结果、托管线程或草稿的读写 API；SQLite schema v6 会删除对应旧表，新数据库不再创建它们。

协议 crate 现也只保留旧控制 `Operation` 的兼容解码标识，不再携带控制请求参数、控制响应结果、命令结果事件、写请求幂等账本或审批决策状态机；这些公开类型没有当前调用者，也不属于只读产品。审批描述与状态仍用于只读展示；旧节点所需的选项字段保留在 wire 对象中，但当前来源固定发送空列表，不再解析、保存或传播 `availableDecisions`。来源世代错误仍用于拒绝过期监控上下文。协议 3 项、App Server 适配器 6 项和来源服务 27 项聚焦测试通过，统一前端重新打包通过，`nekodex-shell` 单并发静态检查通过。

旧 P0 的会话生命周期、持久化和文件审批可执行探针也已从当前工作树移除，README 不再提供运行入口，避免后续开发误触写入控制链路。历史实验结论保留在 P0 文档中，原始脚本仍可从 Git 历史提交 `e09a1a7` 查阅。

当前运行代码也不再沿用 P0 阶段命名：统一前端启动探针与 Tauri 命令已改为 `app_environment`，适配器测试客户端使用独立测试名称，Android `buildSrc` 源码目录移出旧 `p0` 路径。前端生产打包和 `nekodex-shell` 单并发静态检查通过；该纯命名迁移不触发 Android 重打包或全工作区测试。

统一前端只使用应用自定义 `invoke` 命令，不调用 Tauri core 的路径、事件、窗口、WebView、资源、菜单或托盘 JS API，因此 WebView capability 已从整组 `core:default` 收窄为空权限清单；桌面托盘和窗口生命周期仍由可信 Rust 侧直接管理。CSP 同时删除旧 P0 echo 探针的 `ws://127.0.0.1:18789`，当前 WebView 只允许本地资源与 Tauri IPC，设备组网络完全由 Rust 管理；对应历史探针也已移出工作树。Tauri 重新生成的 capability 清单确认 `permissions: []`，`nekodex-shell` 单并发静态检查通过；后续 Linux release 与 Android Debug 包均已使用该配置重新构建并启动，运行证据见本节后文。

传输层随后增加协商式紧凑载荷帧，并保留旧节点回退。40 KiB 二进制业务载荷在两个新节点间的加密往返测试通过；新旧节点协商会保持旧格式，并在 20 KiB 旧数组帧超限时于入队阶段拒绝。协议库 6 项、设备核心 57 项测试通过，真实 mDNS 测试仍按设计忽略。当前 Linux release 与 Poke3 Android Debug 包已同时部署该能力，真机成员状态确认双方完成紧凑帧能力协商；Poke3 随后再次读取当前超大会话，返回 11 个回合、12,082 字节、有效后续游标且无错误。

所有非详情监控结果预算随后统一为 40 KiB，状态快照不再保留可能经 Base64 和 response envelope 后逼近最终帧上限的 48 KiB 特例；详情继续使用兼容旧节点的 12 KiB 预算，并把来源端每回合条目上限与 Poke3 展示端统一为 30 项。重新链接桌面来源后，Poke3 最小复测读取到 3 个额度窗口，并成功取得 11 回合、11,963 字节的当前会话详情及后续游标。

2026-09-17 再次检查现有 Linux/Poke3 运行实例时，两端仍分别监听 TCP 8788，并保持一条已认证连接；Poke3 进程和页面均在前台正常运行。但当时宿主与 Arch 容器访问 ChatGPT 用量接口均在 TLS 握手阶段失败，独立只读 App Server 探针相应返回 `account/rateLimits/read` 与 `account/usage/read` 网络错误，因此 Poke3 正确显示来源部分可用而没有额度快照。这次外部网络故障同时暴露出页面只显示“尚无数据”或模糊的“部分不可用”、没有呈现已有具体错误的交互缺口；统一前端现会在总览、额度和日用量区域逐来源显示有界错误，并在待审批读取失败时保留每个失败来源的有界原因，明确区分“暂无数据”与“无法确认”。若整个状态快照请求失败或没有协商对应监控能力，聚合读取也会保留来源 ID 与有界原因，不再退化成纯失败计数；额度和日用量的空状态同时改为“无法确认是否为空”，不会在错误提示下面继续声称正常无数据。项目、会话列表和详情原本已经通过可见状态栏呈现实际请求错误，没有重复增加提示。前端生产资源打包通过（`dist/app.js` 272.9 kB）。随后 Android Debug 包以单 Cargo/Gradle worker 构建成功并覆盖安装到 Poke3；应用数据和设备组身份保留，进程重新启动、TCP 8788 重新监听并恢复一条已认证连接。额度页真机确认会显示“来源暂时无法读取额度”和“无法确认”空状态，长设备 ID 已缩写，原始 `account/rateLimits/read` 网络错误默认折叠到“查看技术详情”，不会再铺满墨水屏；因此这项错误可见性和层级修复已有运行证据，没有继续扩大到其他页面走查。

同一份最新前端随后进入 Linux release `--no-bundle` 增量构建，单 Cargo worker 在 2 分 19 秒内完成。旧 Nekodex 桌面进程被新二进制替换后，Hyprland 确认 `Nekodex` 原生 Wayland 窗口已映射、可见且未隐藏，空闲进程 RSS 约 175 MiB；Linux 重新监听 TCP 8788，Poke3 在约 8 秒内恢复一条已认证连接。因此 PC 与 Android 当前运行实例已经使用同一版前端资源，而不是只在源码层共享界面。

PC/Poke3 的单页视觉对照随后发现一处真实平台差异：Linux WebKit 继承桌面暗色系统的原生按钮文字色，但统一前端为按钮设置浅色背景，未选中的导航和操作按钮因此呈现为空白；Android WebView 上文字正常。共享设计令牌现为所有按钮显式设置 `color: var(--text)`，选中态继续由 `.active`/`.inverted` 覆盖。Linux release 重新映射后截图确认主题、四个导航项和设备组操作按钮文字恢复；同一前端也重新进入 Android Debug 包并覆盖安装到 Poke3，设备进程、TCP 8788 与一条认证连接恢复。此次只验证导致差异的按钮文字，没有扩展为全页面视觉回归。

## 剩余工作

P4 发布准备已开始：Android release Gradle 任务现从被忽略的外部 `keystore.properties` 读取签名配置，缺少配置时明确失败；仓库只提供无秘密的示例文件。Android 自动备份也已关闭，避免系统迁移只恢复普通数据库而无法恢复 Android Keystore 私钥，形成旧名册与新身份的半恢复状态。首批 Linux 产物、版本递增、覆盖升级、身份不可导出边界和发布验收矩阵已记录在 `docs/release-and-upgrade.md`。本轮没有创建密钥、生成正式安装包或执行发布。

Poke3 在屏幕点亮、Nekodex 前台且与 Linux 保持一条 8788 连接时完成一次有界性能快照：TOTAL PSS 80,877 KiB、SWAP PSS 223 KiB；10 秒空闲 CPU 三次采样为 0.0%、0.8%、0.6%，平均约 0.47%。同一时刻 Linux release RSS 为 152,192 KiB、累计 CPU 0.2%，进程已运行约 9.7 小时。该结果满足当前 PSS 与前台空闲 CPU 基线目标，但不替代长时间耗电、系统回收、滚动峰值或多节点验收；完整条件见 `docs/performance-snapshot.md`。

Nix 包的主源码与 React 前端源码已改用锁定 nixpkgs 提供的 `lib.sources.sourceByGlobs` 白名单，`path:.` 打包不再把本地 `target/`、`node_modules`、`dist`、参考图片或其他未跟踪内容带入 derivation。`nix flake check path:. --no-build` 已通过；实际求值后的主源只包含 `Cargo.*`、LICENSE、apps/crates/generated/plugins 与前端构建脚本，前端源只包含 package 锁文件、HTML/CSS 和 `src/main.tsx`。该修改只收窄打包输入，没有更新 flake.lock、依赖或输出契约；为避免再次产生大体积 store 闭包，本轮没有运行 Nix 构建。

`app_environment` 现在返回编译进 Rust 壳层的 Nekodex 版本，PC 与 Android 共用页头会同时显示平台、版本和 IPC 状态。覆盖升级后可以直接在应用内核对实际运行版本，而不再只依赖 APK 文件名或外部包管理器；该字段只读且不增加轮询。统一前端生产打包通过，`dist/app.js` 为 273.0 kB；本轮没有重建 Rust 壳层或 Android 包。

监控主链路的代码纵切已经形成。当前剩余项以真实设备、恢复路径和长期性能验收为主；只有验收暴露出缺陷时才继续修改对应实现，不为扩大范围新增控制功能。
