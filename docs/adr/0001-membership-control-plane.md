# ADR 0001：设备组成员控制面

状态：P0 草案，因果成员模型、SPAKE2 短码交换、签名事件封装与本地防回滚检查点已实现；持久化和网络集成待验证。

## 决定

每台设备持有独立签名身份，组身份与网络地址分离。局域网发现只提供地址候选。新设备通过一次性短码运行成熟 PAKE 协议，获得由邀请成员签名的入组事件与完整成员日志；业务连接同时验证设备密钥和成员资格。

成员日志为签名事件 DAG。事件声明直接父事件，验证者只承认在事件因果历史中仍为有效成员的签发者。撤销对同一设备身份永久生效；加入与撤销并发或无法证明加入早于撤销时，撤销胜出。重新加入必须生成新设备身份。

成员先交换并验证日志，再开放业务流。网络分区期间撤销只能在已收到撤销事件的设备上生效，界面必须显示同步状态。

## P0 必须证明

- 使用成熟 PAKE 库完成短码验证，短码不出现在网络明文中，并绑定组 ID、双方设备 ID 和临时握手值。
- 三节点 A→B→C 加入后，A 离线不影响 B 与 C 验证彼此资格。
- 乱序、重复、冲突事件得到确定结果；事件 ID 冲突、无权签发、被撤销身份复活均被拒绝。
- 设备日志被截断或回滚时拒绝开放业务连接，并提示成员状态需要同步。

## 当前可执行证据

`nekodex-domain` 已实现单一创世事件、直接父事件、因果历史中的签发者资格、缺失父事件等待、循环拒绝、事件 ID 冲突拒绝，以及有效撤销永久优先。公开写入路径只接受通过 Ed25519 验证的成员事件封装；签名使用规范编码并绑定协议域、组、签发者公钥和事件全部字段，自认证成员 ID 防止公钥冒充。测试覆盖 A→B→C、乱序到达、替换/跨组重放/冒充、被撤销成员签发后继事件和循环图。

短码交换使用 RustCrypto `spake2` 0.4.0。SPAKE2 身份绑定协议域、组 ID、双方设备 ID 和双方 32 字节临时随机数；交换后的会话密钥与双方确认值再次绑定有序握手消息。测试覆盖正确短码、组上下文篡改和错误短码，只有双方确认值校验成功后才能继续。独立邀请状态机不接收短码，只管理 PAKE 结果；时间由调用方注入，支持半开过期边界、成功后单次消费、失败总数锁定和滑动窗口限速，并要求调用方在执行 PAKE 前先做准入检查。当前尚未把确认后的设备签名公钥及成员日志接入网络传输；受信组 ID 与创世成员仍必须由配对结果固定，签名验证本身不能决定初始信任。

设备可把当前有效且已认证事件固定为绑定组 ID 的本地检查点；后续日志缺少任何已固定事件、来自其他组或检查点摘要损坏时均拒绝。测试已覆盖截断、跨组、前向扩展和检查点篡改。该机制需要后续接入可靠持久化和业务连接门禁；从未保存过检查点的新设备仍无法仅凭远端自洽日志判断它是否为完整历史。
