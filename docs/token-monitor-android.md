# InkUI for Token-Monitor：Android 指南

InkUI 是独立开发的非官方 Token Monitor 客户端，Android APK 是本仓库唯一产品。包内界面随 APK 发布，原生层读取外部 Hub；账号管理、采集和跨设备汇总由 [Token Monitor](https://github.com/Javis603/token-monitor) 提供。本仓库不开发或维护 Hub，也不直接查询各服务商 API。

最低 Android 10（API 29），当前主要适配 BOOX Poke3。系统 WebView 需支持 JavaScript 模块及页面使用的浏览器 API。安装入口见 [README](../README.md#安装与连接)。

## 连接与数据范围

设置分为“连接、显示、更多”。首次打开直接显示 Hub 地址与密钥表单，点击“连接并保存”，验证成功后自动进入额度页。已有连接时显示地址、状态与最近成功时间；点击“编辑地址与密钥”修改，点击摘要查看网络、Hub 和历史的诊断。编辑时点击“测试并保存”，验证成功后自动保存并读取；失败保留输入和原配置。仅超时、找不到主机、拒绝连接或其他网络不可达错误提供“仍然保存”；认证、格式和接口错误不允许跳过验证。测试进行时禁用重复提交；离开编辑、修改输入或进入后台会取消候选测试，迟到结果不会保存。

显示页集中放置黑白／彩色、六种重点色、额度示例、数据更新频率和墨水屏刷新。配色和频率即时生效；未知设备显示“由系统管理”，隐藏无法使用的清屏按钮。全屏入口保留在看板顶栏，服务商排序入口保留在额度选择面板。更多页仅放清除缓存与关于。清除缓存只确认一次，保留连接、配色、更新频率和服务商顺序。

常用 Poke3 视口同屏编辑地址与密钥，小屏或键盘压缩后以明确的“地址／密钥”步骤按钮切换，分区和完整诊断文字也按按钮分页，不滚动表单。返回先退出输入；离开有修改的表单时可继续编辑或放弃，取消修改恢复已保存配置。

| 来源 | 示例 | 固定 GET 接口 |
| --- | --- | --- |
| Hub | `http://192.168.1.20:17321` | `/api/stats`、`/api/history` |

只配置 Hub 地址与密钥。裸 IP／主机名自动补 `http://`，Hub 默认端口为 `17321`；明确填写协议或端口时按原输入连接。完整地址不含路径、用户名、查询或令牌。`localhost` 指向 Android 设备本身，电脑服务应填写电脑的局域网地址，并确保 Hub 监听与防火墙允许访问。

Hub 密钥输入框始终显示，已有密钥以“已保存”状态标明，不回显原值；直接输入新值即可替换，留空保留同一地址的原密钥。“显示”仅作用于新输入值；点击“移除密钥”在保存时删除，也可撤销移除。更改来源地址不继承旧密钥。保存接口中 `null` 表示保留同一来源密钥，空字符串表示清除。测试使用未保存的输入；修改输入或离开页面会取消测试。认证失败、超时、找不到主机、拒绝连接及接口不符分别提示。

所有用量、会话与活动数据都来自 Hub 的 stats／history 接口。累计会话列表或字段未提供时明确标记缺失，不合并其他来源或自行补齐。会话状态代表采集时的观测，APK 不提供完整对话正文或工具调用详情。

额度是上游采集快照，刷新只重读来源；保留 `updatedAt`、`stale` 与错误状态。百分比和余额的 0 是有效值，缺失不变成 0；费用为估算 USD 金额，不作为账单。活动曲线按真实日期定位，以平滑实线连接已有记录，保留真实零值和首尾留白；没有记录不等于采集失败，接口未提供逐日覆盖状态时也不能认定真实零用量。

## 服务商展示顺序

在额度页点开“全部服务商”（已筛选时显示账号名称），再点“排序”。每个账号卡片单独占一行，同一家服务商的不同账号可分别调整；用“置顶”、上移和下移按钮操作，列表按屏幕高度自动分页，不滚动、不拖动。跨页移动后会跟随被移动的账号，并以边框标记。

修改先保存在草稿中；“保存”后同时应用于额度卡片和服务商选择列表，卡片从左到右、从上到下遵守自定义顺序。“取消”或设备返回键放弃草稿。“恢复默认”先预览默认顺序，仍需保存才生效。保存失败会保留草稿并提示重试。

顺序按 Hub 地址保存在设备本地，重启和清除用量缓存不会删除；切换密钥不改变排序。新增账号追加在已有排序之后，暂时离线的账号保留原排序插槽。账号优先按邮箱、其次账号名或别名识别，套餐和额度变化不影响身份；身份字段改变时按新账号处理。上游若返回无法区分的重复身份，会提示“身份重复”，保留来源顺序并禁用其单独移动，避免将另一账号误认成它。

实现边界是认证 `GET /api/stats` 已返回的字段。额度页显示主要数值、单位和可用刻度；点开每一项，可按按钮分页读取窗口的 used／limit／remaining、两种百分比、实际周期、重置说明、来源、附加标记、窗口标识、边界类型和详细说明，以及所属账号资料。余额明细包括消费、赠送／现金、计划用量、有效期与分批赠额；重置券包含数量、有效期和各券状态；服务商用量包含请求、Tokens、缓存、费用与延迟。这些服务商侧统计不重复加进会话总量。

`metric=credits` 的金额／点数优先保留原值，百分比另作辅助；`metric=spend` 显示已消费。`showMeter=false` 时不画刻度；没有总额的余额不估算百分比。不把缺失当零，也不把未提供上限当成不限额。Kiro Overage、CREDITS 点数、Zed 次数与金额等有明确的服务商规则；未知单位保留为空并在必要时提示。完整数值与主卡片的缩写分开，微小正余额不会四舍五入成零。

覆盖夹具在 `apps/android/ui/fixtures/provider-limits-v0.78.json`：52 个合成源码分支，附固定上游版本、commit 和各 mapper 行号；包含 30 家服务商、MiMo 双产品、四种第三方 adapter、特殊字段与错误状态。值均为合成数据，不包含真实账号响应。额度卡片按显示格式预留数字空间，同组字号、尾注占位和数字基线一致；百分比最多两位并省略尾零，常用币种余额保留两位，极大／极小值可用短科学计数显示，详情保留完整数值。`test_provider_catalog.mjs` 验证投影／缓存往返和语义，`test_quota_presentation.mjs` 验证显示与边界情况。

上游限制：0.68.0 与 0.78.0 的共享额度字段结构兼容，但 0.68.0 不认识 Notion，部分 Cline／WorkBuddy 多账号聚合行为也较旧；APK 无法恢复已被旧 Hub 丢掉的行。火山 Ark 的一条回退分支把 Token 总量放在名为 Requests 的字段，却没有单位标记，客户端不会猜成请求次数或 Token 数。Copilot 没有传递明确的不限额标记时只能保留未知状态。原始服务商没有传到 Hub 的字段，前端同样无法恢复。

## 显示、分页与设备状态

主导航固定为额度、会话、活动、明细四页，支持日／月／累计视图。界面固定视口、无滚动、无动画；额度按账号信息量分配矩形卡片，完整字段通过详情按钮分页读取。服务商筛选菜单与长详情同样分页，账号和窗口不按固定数量截断，只渲染当前页图形。

内容区左划下一页、右划上一页，抬手后整页替换；与翻页按钮一致，首尾停止，不跨主栏目跳转。短距离、纵向、明显斜向、长按、多指及取消手势不翻页；输入框保留输入操作，屏幕边缘留给系统返回手势。

首次启动默认全屏，顶栏可切换并记住选择。Android 10 使用沉浸式系统栏与键盘 `adjustResize`；Android 11+ 使用 WindowInsetsController 处理系统栏、键盘与刘海边距，依据 [Android 沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive) 与 [WebView insets](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets)。

顶栏显示本地时区的 24 小时时间、电量／充电与网络链路。网络链路和 Hub 连接独立：局域网存在但外网未验证，不会被误判为 Hub 断开。缺失状态显示未知。原生层依据 [Android 网络回调](https://developer.android.com/reference/android/net/ConnectivityManager.NetworkCallback#onLinkPropertiesChanged(android.net.Network,%20android.net.LinkProperties)) 在前台比较链路和路由变化，向页面只提供不含网络标识的变化序号；不读取 SSID 或位置，不持久化网络 IP。只使用普通 `ACCESS_NETWORK_STATE` 权限，无位置权限或后台监听；同值事件和设置遮挡的顶栏变化不请求刷新。

黑白模式采用 16 阶灰度；亮色模式提供蓝、青、绿、琥珀、玫瑰、紫六种重点色。配色可用于普通彩屏，但实体彩色墨水屏尚未验收。

## 墨水屏刷新

数据读取与屏幕刷新分别处理。原生刷新等待 WebView 提交新画面，同帧变化合并、数据变化短暂节流；相同画面和屏幕阅读器专用的隐藏文字变化不额外刷新，时钟变化不重建未变的网络和电量图形，后台取消待执行工作。刷新预算按实际派发计数，合并或取消的翻页不重复计数。画面提交回调超过 2 秒时最多重试一次，连续失败保留待刷意图，等下一次真实画面变化或恢复前台再试；超时不会跳过画面提交保障直接硬刷。

- Poke3 默认 GC16 局部模式，保留 16 级灰度；每 6 次翻页或累计 30 次实际局部更新请求全刷。配色切换、恢复前台和“设置 → 显示 → 立即清屏”请求全刷，没有数据变化时不按定时器空刷。
- 适配基于 Poke3 Android 10 框架公开的 `View.getDefaultUpdateMode()`／`setDefaultUpdateMode(int)` 与普通 `invalidate()`，只为本次重绘设置模式，随后恢复；不修改系统刷新设置，不引入厂商 SDK。灰度局部／全刷语义参考 [Onyx 官方更新模式说明](https://github.com/onyx-intl/OnyxAndroidDemo/blob/ec512c79c0d39c1e294214d36580ce4c914bbea6/doc/EPD-Update-Mode.md)，固件指纹与框架校验值记录在原生适配类中。
- 未验证机型、缺少接口或调用失败时由系统管理刷新，并禁用硬件清屏按钮。不用网页黑白闪屏模拟硬件全刷；其他机型的专用彩色刷新波形尚未适配或实测。

## 连接、缓存与刷新策略

Hub 原密钥同时可授权写接口；APK 只转发上述两个固定 GET，不接受任意 URL、Cookie 或页面提供的请求头。需要真正的权限隔离时，应自行提供只读认证入口。HTTPS 正常校验证书；HTTP 没有传输加密，应在可信网络使用。

包内页面使用固定虚拟 HTTPS 来源，阻止外部页面、文件访问、弹窗和导航。凭据以 Android Keystore 的 AES-GCM 密钥加密，经 AtomicFile 写入 `noBackupFilesDir`，关闭备份；页面只能读取地址、配置版本和密钥是否已保存，不内置个人连接配置。

网络不跟随重定向、不使用系统代理；连接与读取各有 8 秒超时，响应上限 8 MiB。未保存连接测试使用相同校验，10 秒总截止，异步运行且仅有一个有效测试；退后台取消，结果不返回响应正文或密钥。

统计与历史分别缓存最近成功的展示字段，断线明确标记缓存。额度详情可包含账号姓名／邮箱和账务展示信息；私有 ID、密钥、Cookie、请求头及任意原始响应不进入页面缓存。切换来源清除展示缓存并丢弃旧请求，保留外观和刷新偏好；清缓存需再次确认，不清除连接配置。

默认每 60 秒读数据，可选 5 分钟或手动。退后台停读并断开进行中的请求，回前台恢复；没有常驻服务或唤醒锁。返回键先退出输入、详情或设置，再回桌面。

## 连接记忆与断线恢复

设备加密保留最后保存的 Hub 地址与密钥；切换 Wi-Fi、断网和重启不会清除。Wi-Fi／路由恢复后等待 1 秒合并短暂变化，再尝试同一个已保存地址；旧网络的迟到响应不能确认新网络已连接。局域网无需通过外网验证。暂时不可达时，自动更新模式依次在 15、30、60、120、300 秒后重试，之后保持 5 分钟间隔；成功后恢复所选的正常频率。手动档没有定时重试，只在主动刷新、恢复前台或回网时读取一次。认证失败、跳转或数据不符等待“重试”或修改配置，不循环提交无效密钥。

地址可填写 IP 或当前网络能解析的主机名，例如 `hub.example.lan:17321`；始终保存原输入的主机名，不把解析结果改存为固定 IP。主机名对应地址由网络的 DNS 管理；DNS 更新后可继续连接。裸计算机名和 `.local` 在不同路由器／Android 版本上不保证可用。2026-10-26 在当前 Poke3 网络实测无法解析目标电脑的裸主机名和 `.local` 名称，因此保留原 IP 配置。

核对 [上游 Hub 源码](https://github.com/Javis603/token-monitor/blob/7f14812656344cd915a57bdeb25ea746ae439e99/src/hub/server.js) 后，当前没有 mDNS／DNS-SD 自动发现或固定 Hub 实例身份；构建标记也不能代表同一台电脑。客户端不扫描子网，也不把已保存密钥发送到猜测的地址。IP 改变而主机名不可用时，需要编辑地址并验证；改变来源地址仍须重新填写密钥。

## 构建与签名升级

需要已有 JDK 17+、Android SDK platform 36 及匹配 build-tools。Gradle wrapper 为 8.14.3，Android Gradle Plugin 为 8.11.0；首次解析依赖需要网络或已有缓存。在仓库根目录执行：

```bash
export JAVA_HOME=/path/to/jdk
export ANDROID_HOME=/path/to/android-sdk
tools/build-eink-apk.sh debug
```

Debug 输出 `output/android/inkui-debug.apk` 及 `.sha256` 文件，包名 `dev.tokenmonitor.eink.debug`，开启应用与 WebView 调试。模型及原生策略检查入口见 [README](../README.md#开发)。

Release 使用长期保存的私有签名配置，字段见 [keystore.properties.example](../apps/android/keystore.properties.example)。密钥及密码放在仓库外：

```bash
export TOKEN_MONITOR_SIGNING_FILE=/private/path/release.properties
tools/build-eink-apk.sh release
```

输出 `output/android/inkui-release.apk` 及 `.sha256` 文件，包名 `dev.tokenmonitor.eink`，关闭应用及 WebView 调试。缺少签名配置时构建失败。覆盖升级必须保持相同包名与签名，并使用不低于已安装包的 `versionCode`；交付新的开发构建时递增内部构建号；请长期保留发布密钥。

首个公开版本统一为 **v1.0.0**，`versionCode` 为 12。发布资产命名为 `InkUI-for-Token-Monitor-v1.0.0.apk` 和 `SHA256SUMS`；安装下载与校验值以 [发布页](https://github.com/Shangshui0302/InkUI-for-Token-Monitor/releases/latest) 为准。

## 版本号

首个公开版本从 **1.0.0** 开始，正式版本以 GitHub Release 为准。之前误用的内部迭代编号已更正。

| 变更类型 | 版本字段 | 示例 |
| --- | --- | --- |
| 不兼容变更 | 主版本增加，次版本和修订版本归零 | `1.4.2 → 2.0.0` |
| 向后兼容的新功能 | 次版本增加，修订版本归零 | `1.0.3 → 1.1.0` |
| 问题修复、局部排版或性能优化 | 修订版本增加 | `1.0.0 → 1.0.1` |

- `versionName` 面向用户，遵守上述规则；开发期间用目标版本加 `-dev`，不因每次界面微调增加公开版本号。
- `versionCode` 是独立的 Android 内部构建号，新交付构建递增；重新规划公开版本时也不回退，保证已有安装可覆盖升级。
- 当前正式包为 **1.0.0，构建 12**，文件名为 `InkUI-for-Token-Monitor-v1.0.0.apk`；“更多”和“关于”同时显示版本与构建号。Git 标签、Release 标题、安装包名称和 APK 内版本保持一致。
