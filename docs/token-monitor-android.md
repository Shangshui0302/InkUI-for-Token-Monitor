# Android APK 指南

APK 是唯一产品。`apps/android/` 在构建时将 `ui/` 内的页面编入安装包；原生层连接外部数据源。最低 Android 10（API 29），当前目标为 Poke3；系统 WebView 需支持 JavaScript 模块及页面使用的浏览器 API。

## 连接与数据范围

首次打开进入连接页，通过“上页／下页”填写来源并“保存并连接”；设置中的“编辑”可修改连接，“连接”可分页查看状态及完整地址。

| 来源 | 示例 | 固定 GET 接口 |
| --- | --- | --- |
| Hub | `http://192.168.1.10:17321` | `/api/stats`、`/api/history` |
| 归档，可选 | `http://192.168.1.10:18788` | `/api/session-archive` |

两项来源独立配置地址与密钥。地址只填写 `http(s)://主机:端口`，不含路径、用户名、查询或令牌。输入留空保留同一来源的已有密钥；“清除”在保存时删除。更改来源地址时不继承旧密钥。保存接口中，`null` 表示保留同一来源密钥，空字符串表示清除。

Hub 提供汇总快照和历史，不提供完整本机会话归档。APK 仅兼容已有外部归档服务；本仓库不提供或维护服务实现。归档接口以 Bearer 密钥认证，返回含布尔值 `available`、会话对象 `sessions` 和可选时间 `capturedAt` 的 JSON；会话对象按稳定会话标识索引，读取允许的用量与展示字段。

归档按 `local-device` 处理，只代表来源电脑已有留存，不代表跨设备完整历史，不会重复累加进 Hub 总量。未配置归档、来源错误或读取失败分别提示，不把缺失当成零。会话最近观测状态不保证实时运行；APK 不提供完整对话正文或工具调用详情。

额度是上游采集快照，刷新只会重读来源；账号的 `updatedAt`、`stale` 与错误状态分别保留。百分比和余额的 0 是有效值，缺失不变成 0；费用为估算 USD 金额，不作为账单。

实现边界是认证 `GET /api/stats` 已返回的字段。额度页显示主要数值、单位和可用刻度；点开每一项，可按按钮分页读取窗口的 used／limit／remaining、两种百分比、实际周期、重置说明、来源、附加标记、窗口标识、边界类型和详细说明，以及所属账号资料。余额明细包括消费、赠送／现金、计划用量、有效期与分批赠额；重置券包含数量、有效期和各券状态；服务商用量包含请求、Tokens、缓存、费用与延迟。这些服务商侧统计不重复加进会话总量。

`metric=credits` 的金额／点数优先保留原值，百分比另作辅助；`metric=spend` 显示已消费。`showMeter=false` 时不画刻度；没有总额的余额不估算百分比。不把缺失当零，也不把未提供上限当成不限额。Kiro Overage、CREDITS 点数、Zed 次数与金额等有明确的服务商规则；未知单位保留为空并在必要时提示。完整数值与主卡片的缩写分开，微小正余额不会四舍五入成零。

覆盖夹具在 `apps/android/ui/fixtures/provider-limits-v0.78.json`：52 个合成源码分支，附固定上游版本、commit 和各 mapper 行号；包含 30 家服务商、MiMo 双产品、四种第三方 adapter、特殊字段与错误状态。值均为合成数据，不包含真实账号响应。`test_provider_catalog.mjs` 验证投影／缓存往返和语义，`test_quota_presentation.mjs` 验证显示与边界情况。

上游限制：0.68.0 与 0.78.0 的共享额度字段结构兼容，但 0.68.0 不认识 Notion，部分 Cline／WorkBuddy 多账号聚合行为也较旧；APK 无法恢复已被旧 Hub 丢掉的行。火山 Ark 的一条回退分支把 Token 总量放在名为 Requests 的字段，却没有单位标记，客户端不会猜成请求次数或 Token 数。Copilot 没有传递明确的不限额标记时只能保留未知状态。原始服务商没有传到 Hub 的字段，前端同样无法恢复。

## 全屏、设备状态与服务商选择

首次启动默认全屏。顶栏的展开／收拢图标可进入或退出全屏，原生保存选择，重启和回到前台继续沿用；系统栏仍可通过系统边缘手势临时唤出。Android 10 用沉浸式系统栏标志并保留键盘 `adjustResize`；Android 11+ 使用 WindowInsetsController，在安全容器内处理系统栏、键盘和刘海边距，避免新 WebView 重复应用边距。行为依据 [Android 沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive) 与 [WebView insets](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets)，当前各版本真实键盘行为仍待设备验收。

顶栏时间来自设备本地时区，24 小时制、每分钟更新；电量百分比、充电和网络链路由原生前台监听提供。Wi-Fi／有线／移动网络、断开、未知分别显示对应图标；局域网链路存在但外网未验证仍显示该链路，不把它当作 Hub 不可用。Hub 连接图标独立，点开可读完整状态与最近读取时间。没有字段时显示未知，不用 0 冒充电量；不读取 SSID、IP、位置或网络标识。仅增加普通 `ACCESS_NETWORK_STATE` 权限，无位置权限、运行时权限申请、秒级轮询或后台监听；同值事件和被设置页遮住的顶栏变化不会请求墨水屏刷新。

额度筛选改成带边框、下拉箭头及展开状态的控件；展开后“全部服务商”和各账号使用选中勾，按钮或轻扫翻页，保持无滚动。取消／返回／Escape 收起而不改变已选账号；支持键盘选择。缺少账号标签且同名时保留账号编号以区分，主卡片移除无意义序号和重复计数。常用 Poke3 视口下服务商名称约 18px 加粗，账号、套餐和窗口分层，完整字段仍在详情里读取。刷新、设置、全屏、返回及主分页以图标呈现，均保留可访问名称。

## 轻扫翻页与墨水屏刷新

内容区左划下一页、右划上一页，与“上页／下页”按钮一致；抬手后整页替换，不平移、拖动或动画，首尾停止，不跨主栏目跳转。额度、服务商目录、会话、活动分段、明细和字段详情共用分页；设置里的长连接状态及编辑步骤也支持轻扫。短距离、纵向或明显斜向移动、长按、多指及取消的手势不翻页；输入框保留输入操作，屏幕左右边缘留给系统返回手势。按钮始终保留。

数据刷新（设置 → 数据）与屏幕刷新（设置 → 屏幕）分别处理：

- 原生刷新等待 WebView 提交新的画面。同帧变化合并，数据更新短暂合并节流，相同可见内容不额外请求屏幕刷新；后台取消待执行工作。
- Poke3 默认采用 GC16 局部模式，保留 16 级灰度；每 6 次翻页或累计 30 次实际局部更新触发全刷。切换配色、恢复前台及手动“清屏”直接请求全刷。没有数据变化时不会按定时器空刷。
- 原生适配基于已连接 Poke3 的 Android 10 框架：公开 `View.getDefaultUpdateMode()`／`setDefaultUpdateMode(int)` 和普通 `invalidate()`，模式只作用于本次重绘后恢复。未调用受限制的隐藏接口，不修改系统刷新设置、不引入厂商 SDK。灰度局部／全刷语义参考 [Onyx 官方更新模式说明](https://github.com/onyx-intl/OnyxAndroidDemo/blob/ec512c79c0d39c1e294214d36580ce4c914bbea6/doc/EPD-Update-Mode.md)，设备固件指纹与框架校验值记录在原生适配类中。
- 其他厂商、未经验证的机型、缺少接口或调用失败时回退到系统重绘；设置显示“由系统管理刷新”并禁用硬件清屏按钮。没有用网页黑白闪烁冒充全刷。彩色配色仍可用，但尚未实现其他机型的专用彩色刷新波形。

刷新逻辑已有设备接口只读核对、浏览器触摸检查与原生策略验证；1.1.0 已安装并启动，但物理全刷和残影改善仍需真机观察。

## 安全、缓存与刷新

Hub 原有密钥同时可授权写接口；APK 仅提供固定 GET，不能据此称上游密钥只读。需要真正限制客户端权限时，应使用外部提供的只读认证入口。

- 包内页面使用固定虚拟 HTTPS 来源，阻止外部页面、文件访问、弹窗和页面导航。原生层只转发三个固定 GET，不接受任意 URL、Cookie 或页面提供的请求头。
- 凭据使用 Android Keystore 的 AES-GCM 密钥加密，经 AtomicFile 原子写入 `noBackupFilesDir`，备份关闭。页面只能读取地址、配置版本和密钥是否已保存；APK 不内置个人地址或凭据。
- 网络不跟随重定向、不使用系统代理，HTTPS 正常校验证书；HTTP 没有传输加密。连接和读取各有 8 秒超时，响应上限 8 MiB。
- 统计、历史、归档分别缓存最近成功的展示字段。认证额度详情可包含账号姓名／邮箱及账务展示信息；账号私有 ID、密钥、Cookie、请求头和任意原始响应不进入页面缓存。切换来源清除数据缓存并丢弃旧请求结果，保留显示和刷新偏好；断线明确标记缓存。
- 默认 60 秒刷新，可选 5 分钟或手动。退后台停读并断开进行中的原生请求，回前台恢复；没有常驻服务或唤醒锁。返回键先退出输入、字段详情或设置，再回桌面。

## 构建与签名升级

需要已有 JDK 17+、Android SDK platform 36 及匹配 build-tools；Gradle wrapper 为 8.14.3，Android Gradle Plugin 为 8.11.0。首次解析依赖需要网络或已有缓存。

Debug 构建与模型／原生策略检查见 [README](../README.md)。Debug 输出 `output/android/token-monitor-eink-debug.apk` 及 SHA-256 文件，包名为 `dev.tokenmonitor.eink.debug`，开启应用与 WebView 调试。

Release 使用长期保存的私有签名配置，字段见 [keystore.properties.example](../apps/android/keystore.properties.example)。真实密钥及密码放在仓库外，在仓库根目录执行：

```bash
export TOKEN_MONITOR_SIGNING_FILE=/private/path/release.properties
tools/build-eink-apk.sh release
```

输出 `output/android/token-monitor-eink-release.apk` 及 SHA-256 文件；包名 `dev.tokenmonitor.eink`，关闭应用及 WebView 调试。缺少签名配置时构建失败。覆盖升级须保留相同包名和签名，并增加 `versionCode`；勿丢失发布密钥。

## 历史验收与当前边界

2026-10-25，Release 1.1.0（versionCode 2）已在 Poke3 Android 10 上覆盖安装并冷启动成功；保留原有应用数据、配置与缓存。已确认自适应额度页、全屏及设备时间／电量／网络栏显示，设备安装包 SHA-256 与本地构建一致：`f1d0b0171f4c63186c7c585b72d5c4a47016b858d3c7a85cdb83d4a599c1a965`。此次安装没有重新执行全部页面、实时 Hub 读取、物理清屏波形或长期残影验收；相关浏览器与模型测试证据分列如下。

自适应卡片版通过 72 项 JS 测试。布局测试覆盖 35 组视口、零窗口、33 窗口及 128 账号×32 窗口：Poke3 三账号样例中，三个卡片面积不同、余额小卡不再占整行，卡片覆盖约 97% 内容区（扣除分隔空隙）。规划压力测试在当前开发机 Node 上约 20ms，不代表 Poke3 耗时。浏览器在 8 种视口中完整遍历 52 个合成源码分支的 121 项入口，另验证券、资料、重复账号、长名称和 33 窗口；Poke3 横屏下完整样例由上一版的 26 页减为 20 页。实际渲染检查包括无滚动、卡片无重叠／越界、所有入口可达；放大后的数字裁边问题修复后，在受影响的 5 种视口重新检查 84 个状态，数字无横向省略或纵向裁切。值变化保持卡片几何不变，零张与未知券、详情及抬手翻页仍正常。这些均是合成数据和模拟视口结果；本次真机证据范围见本节开头。
