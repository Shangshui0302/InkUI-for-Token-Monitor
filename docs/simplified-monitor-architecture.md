# Nekodex 简化监控架构

状态：已接受

日期：2026-09-17

优先级：取代现有 App Server 来源链路，作为后续开发的唯一基线

当前实现：`tools/codex-status-server.py` 已提供单机只读采集器和浏览器页面；Tauri/Android 壳切换到该接口仍是后续迁移步骤，不把旧来源链路的运行结果当作新方案的验证。

## 决策摘要

Nekodex 的首要目标是稳定展示 Codex 已经写入本机的只读状态，而不是复刻 Codex 客户端、托管 App Server 或建设通用分布式协议。

新实现直接只读 `CODEX_HOME` 下的 SQLite、索引和 rollout 日志，生成一个独立状态快照，通过局域网 HTTP 接口提供给 PC 与 Poke3 的同一套前端。额度、任务、活动和会话分别采集、分别报错；任何单项失败都不得终止采集服务或清空其他成功字段。

参考实现 [Anything Codex Status](https://github.com/ParkerGong/anything-codex-status)（调研提交 `32153e2`）已证明这条路径可行：它不启动 App Server，也不请求 OpenAI 在线接口，而是从 `state_5.sqlite`、`session_index.jsonl` 和 `rollout-*.jsonl` 读取当前任务、额度样本和最近活动。本机只读验证也已取得当前任务、额度/用量、运行状态和最近活动。因此，首版不再以 App Server 为主数据源。

## 产品边界

首版必须提供：

- 当前任务及 `RUNNING`、`READY`、`UNKNOWN` 状态；
- 最近用户消息、Codex 回复和工具活动的有界摘要；
- rollout 中最近一次有效的 5 小时、周额度及重置时间；
- 当前工作区的会话列表与必要的只读摘要；
- PC 与 Poke3 共用的响应式、墨水屏友好界面；
- 局域网内的只读访问和明确的来源更新时间、错误状态。

首版明确不提供：

- 创建任务、发送消息、停止任务或处理审批；
- App Server daemon/proxy 管理；
- 实时接管其他 Codex 客户端中的会话；
- 通用事件回放、跨来源事务、离线写队列或复杂能力协商；
- 云端中转、公开互联网暴露或未经验证的平台安装包。

## 目标结构

```text
~/.codex/state_5.sqlite
~/.codex/goals_1.sqlite（存在时）
~/.codex/session_index.jsonl
~/.codex/sessions/**/rollout-*.jsonl
~/.codex/accounts/registry.json（存在时）
              │
              ▼
       本机只读采集器
       - SQLite 只读连接
       - JSONL 尾部有界扫描
       - 字段级错误隔离
              │
              ▼
       GET /api/status
       GET /api/sessions
       GET /healthz
              │
       ┌──────┴──────┐
       ▼             ▼
     PC 页面       Poke3 页面
```

采集器是唯一业务后端。前端不理解 SQLite、rollout 格式、App Server 或设备协议，只消费稳定 JSON。局域网发现、设备目录和访问控制即使保留，也只能位于 HTTP 状态接口之外，不能参与或阻断本机采集。

## 数据读取规则

### 当前任务与会话

- 从 `state_5.sqlite` 的线程表读取当前工作区最近更新且未归档的非子代理会话。
- 工作区没有匹配项时，可以回退到最近活动会话，但响应必须标记为回退结果。
- `session_index.jsonl` 只用于补充用户可读短标题，不作为会话存在性的唯一依据。
- rollout 路径必须来自本机状态库或受控的 `CODEX_HOME` 范围；不得接受远端任意文件路径。

### 状态与活动

- 只扫描 rollout 尾部的有限字节，不把完整历史载入内存。
- 最新用户消息晚于最终回复时为 `RUNNING`；最终回复不早于最新用户消息时为 `READY`；缺少足够证据时为 `UNKNOWN`。
- 最近活动对连续重复事件去重并设置固定条数上限。
- 文件正在追加、单行损坏或未知事件类型时跳过该行，并在诊断字段记录部分可用，不得令整个接口失败。

### 额度

- 从 rollout 的 `token_count.rate_limits` 读取最近一次有效样本。
- 当前样本为空或明显无效而本次扫描窗口内存在较新的有效样本时，可以回退到该有效样本，并标记 `stale: true` 与实际采集时间。
- 首版不调用 `account/rateLimits/read`、`account/usage/read` 或其他在线接口。网络故障不能影响本地额度、活动和会话读取。

### 账户与目标文件缺失

- 账户注册表、目标数据库或字段不存在时返回对应字段的 `unavailable`，其他字段照常返回。
- Codex 版本导致 schema 变化时，采集器应报告具体不兼容字段；不得退出常驻服务。

## 最小接口契约

`GET /api/status` 返回单机摘要：

```json
{
  "generated_at": "2026-09-17T00:00:00Z",
  "source": { "device_id": "...", "device_name": "...", "state": "ok" },
  "task": { "state": "running", "thread_id": "...", "title": "...", "workspace": "..." },
  "quota": { "state": "ok", "observed_at": "...", "windows": [] },
  "activity": { "state": "ok", "items": [] },
  "sessions": { "state": "ok", "count": 0 },
  "errors": []
}
```

每个域的 `state` 只有 `ok`、`stale`、`unavailable`。顶层 HTTP 500 仅用于服务本身无法形成任何响应的情况；单个域读取失败仍返回 HTTP 200，并在 `errors` 中给出稳定错误码和简短信息。

`GET /api/sessions?workspace=...&cursor=...` 返回有界分页列表。首版不提供任意会话全文读取；确需摘要时，只返回界面所需的短文本和时间信息。

`GET /healthz` 只表示服务进程可响应，同时给出最近一次成功采集时间。它不把额度在线、存在活动或当前有运行任务当作健康条件。

## 刷新与性能

- 前端默认每 3 秒请求一次本机快照；窗口不可见时降低频率或暂停。
- 采集器可以缓存最近一次解析结果，但缓存只是性能优化，不引入持久化事件系统。
- `state_5.sqlite` 使用只读 URI 和短超时；JSONL 只读取尾部有限字节。
- 同一刷新周期内共享一次文件读取；不设置跨设备请求合并、来源世代、事件游标或回放协议。
- 采集失败保留上次成功字段时必须标记 `stale`，并保留原始采集时间。

## 局域网与设备组

首版允许两种部署方式：

1. Poke3 保存一台来源电脑的地址并直接读取；这是最快上线路径。
2. 保留一个轻量设备目录，让一次加入后获得组内来源地址列表；查看端随后直接请求各来源的状态接口。

第二种方式不得重新引入分布式状态复制。成员关系只回答“有哪些来源和地址”，业务数据始终由来源电脑本机读取并直接返回。发现或设备目录不可用时，已知地址仍应可访问。

默认只监听本机或明确选择的局域网地址。采集器在绑定非 localhost 地址时强制要求 `CODEX_STATUS_TOKEN`，浏览器通过本地输入框发送 Bearer 令牌；令牌不写入 URL、日志或界面截图。公网部署和复杂权限系统不属于首版。

## 保留与删除

保留：

- `apps/ui` 的统一响应式界面与墨水屏样式；
- Poke3 应用壳、签名、版本和覆盖升级配置；
- 必要的设备名称、来源地址保存和最小只读访问凭据；
- 已有历史文档，作为旧实现证据，不作为新架构约束。

从运行主链路移除：

- `crates/appserver-runtime`；
- `crates/appserver-adapter`；
- 当前 `crates/source-service` 的 App Server 后端；
- shared daemon、proxy 和 isolated fallback 两套来源模式；
- 业务能力协商、来源世代、事件回放、审批监控和 100 MiB 离线缓存；
- 为上述机制服务的 UI 操作、状态文案和测试矩阵。

设备身份、PAKE、Noise 和签名成员日志不自动判定为保留。只有在轻量设备目录方案中确实比“地址 + 随机只读令牌”更省实现和运维成本时才复用；否则退出首版主链路。

## 迁移顺序

### M1：单机采集器

- 建立稳定 JSON 模型；
- 只读解析本机数据库、索引和 rollout；
- 用当前真实 `CODEX_HOME` 验证任务、额度、活动和会话计数；
- 单项故障不得影响其他字段。

完成条件：不启动 App Server、不访问 OpenAI 网络接口时，`/api/status` 能持续返回当前真实状态。

当前本地验证命令：

```bash
CODEX_HOME="$HOME/.codex" CODEX_STATUS_WORKSPACE="$PWD" \
python3 tools/codex-status-server.py --host 127.0.0.1 --port 8765
curl http://127.0.0.1:8765/healthz
curl http://127.0.0.1:8765/api/status
curl http://127.0.0.1:8765/api/sessions
```

当前验证已确认：真实宿主数据可返回任务、额度窗口、最近活动和会话数量；服务不需要 App Server 或外网可用。

### M2：统一前端接入

- 将总览、额度、活动和会话页切换到新接口；
- 删除共享 daemon、来源重启和审批相关交互；
- PC 与 Poke3 使用同一前端资源。

完成条件：PC 与 Poke3 对同一响应呈现一致；断网时本地历史仍可读取。

### M3：局域网交付

- 先完成单来源地址保存和只读访问；
- 再决定是否加入轻量设备目录；
- 不把多节点发现作为 M1、M2 的前置条件。

完成条件：Poke3 能在局域网读取一台 Linux 来源的真实额度和会话；来源不可用时显示明确错误，不影响应用其余页面。

### M4：删除旧主链路

- 移除不再编译或调用的 App Server、事件和复杂协议代码；
- 删除失效测试、生成协议和旧运行入口；
- 更新构建配置、运行手册和发布清单。

完成条件：源码和用户文档中不存在两套可被误用的状态采集路径。

## 首版验收

只执行一次核心冒烟：

1. 在运行 Codex 的 Linux 电脑启动采集器；
2. `/healthz` 正常，`/api/status` 在 1 秒内返回；
3. 当前任务、最近活动、至少一个额度窗口和会话计数来自真实本机数据；
4. 临时阻断外网后，接口仍返回本地数据；
5. 制造一个可恢复的单字段读取失败，其他字段仍正常；
6. Poke3 能读取并展示同一快照；
7. 远程写入、任务控制和审批入口不存在。

不为首版增加长时间待机、极端网络、复杂撤销收敛、共享 daemon、App Server 版本矩阵或全平台安装包测试。真实使用出现具体问题后再补对应验证。

## 历史实现定位

现有复杂实现及其运行证据并非无效，但它验证的是更大范围的设备组、加密传输、App Server 和恢复协议。它们从本决策起属于历史实现和可选素材，不能继续增加首版成本，也不能作为保留代码的默认理由。
